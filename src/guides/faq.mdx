## About ClearedStack v3.1

### Is it really free?

Yes. There is no paid tier, no trial, no ads, no sponsorship, and no donation button. The project takes in no revenue. Shipped tools run in your browser, and the entire 17-pod v3.1 platform (7 control-plane pods plus 10 deterministic workers) fits on a single 4 GiB `k3s` node.

### Who runs it?

It is an independent personal project, built on personal time with personal equipment. It is not affiliated with, endorsed by, or sponsored by the Department of Defense or any other government agency. See the [About](/about/) page for the full statement.

### What are the live Command Portal and App Store?

In v3.1, `clearedstack.com` pairs its contractor-first catalog (`/tools/`) with live operational factory views under `/guides/`. The **Command Portal** (`/guides/live-command-portal/`) uses deterministic priority rules to float `P0` errors, `P1` stalled queues, and `P2` pending decisions or edits to the top while collapsing quiet idle workers to one line. The **App Store** (`/tools/#apps`) displays CasaOS-style cards for every running app and worker with live version, health, and sanitized errors, plus owner-only 1-click **Install / Upgrade / Pause / Rollback** controls. See [Live Command Portal](/guides/live-command-portal/) and [Software decides the UI](/guides/software-decides-ui/).

### Why is there no login lock?

ClearedStack v3.1 is an open public sandbox. Anyone can browse the Command Portal, inspect running workers, read sanitized error codes, and propose edits using the `✎` button without signing in. To prevent abuse without requiring accounts or CAPTCHAs, public edits pass through a 5-layer shield: a ~1-second browser Proof-of-Work puzzle, a hidden honeypot field, a daily-salted IP hash rate limit, strict `ownership_map.json` schema validation (4 KB max, scripts stripped), and a human approval gate in `cs-04-decide`. See [Open public sandbox](/guides/open-public-sandbox/) and [Anonymous edits and anti-spam](/guides/anonymous-edits-and-anti-spam/).

### What license does ClearedStack use?

Every repository in ClearedStack v3.1—`clearedstack.com`, `cs-01` through `cs-10`, `cs-git`, `cs-registry`, `cs-runner`, and `cs-store`—is released under the **MIT License**. All Go and web code is written clean-room from scratch; while inspired by ideas from Forgejo, Argo CD, and CasaOS, zero upstream code is copied. See [MIT clean-room architecture](/guides/mit-clean-room-architecture/).

### Does the name mean I am “cleared” for something?

No. The name is only a name. ClearedStack does not grant, verify, or imply a security clearance, a facility clearance, an authorization to operate, or a certification such as CMMC or FedRAMP.

## 10 deterministic workers and zero AI at runtime

### Is AI used when the tools or workers run?

No. ClearedStack v3.1 has **zero AI at runtime** across all 10 pipeline workers (`cs-01-intake` through `cs-10-notify`) and all shipped tools. There are no LLMs, no API calls to AI providers, and no token costs at runtime, so the same input produces the exact same output on any cluster. AI may be used as an authoring aid under human review, never inside running workers or tools. See [How AI is used to build this project](/guides/built-with-ai/).

### How do the 10 workers handle unusual cases without AI?

Each worker repo supports deterministic sub-tools under `tools/<case>/` listed in `tools/registry.yaml`. When a worker encounters an unfamiliar page or layout, it fails closed, pauses the item in `needs_subtool`, and `cs-10-notify` opens a fingerprinted task in the owning repo. Once a deterministic sub-tool and golden test fixture are added and built, `hub-queue-api` automatically replays all queued items for that pattern. See [Deterministic sub-tools](/guides/deterministic-sub-tools/).

### How does `cs-02-observe` handle JavaScript-heavy sites?

`cs-02-observe` runs as a lightweight Go HTTP pod (~30 MiB RAM) for standard public pages and spawns on-demand headless browser `Job` pods only when a target site requires JavaScript rendering.

## Infrastructure, no Docker, and GitHub mirror

### Why is there no Docker?

ClearedStack v3.1 uses **zero Docker anywhere**. `cs-runner` listens to `cs-git` push webhooks and spawns ephemeral Kubernetes build Jobs inside `k3s` + `containerd`: `ko` builds Go workers directly into OCI images, and rootless BuildKit builds the Next.js Portal. Images are signed with `cosign` and stored in the internal `cs-registry` OCI store, which keeps the last 5 digests per app for instant rollback. See [cs-registry and no Docker](/guides/cs-registry-and-no-docker/) and [cs-runner and cs-store](/guides/cs-runner-and-cs-store/).

### What is GitHub used for?

GitHub is a **public code-only mirror**. The internal `cs-git` service is the source of truth for all repositories and automatically pushes commits on `main` and tags to GitHub when changes are detected. **Zero container images are ever pushed to or stored on GitHub.** See [cs-git and the GitHub mirror](/guides/cs-git-and-github-mirror/).

### How are cluster internals protected if the Portal is public?

The cluster uses a **2-namespace topology**: `clearedstack` holds the 7 control-plane pods (`clearedstack-web`, `hub-queue-api`, `postgres`, `cs-git`, `cs-registry`, `cs-runner`, `cs-store`) and `cs-workers` holds all 10 workers (`cs-01` through `cs-10`). Only `clearedstack-web` has a public Ingress. `NetworkPolicy` rules isolate internal traffic, `cs-store` strips node names, pod hostnames, and internal IPs before reporting health, and the public Portal reads only from sanitized `pub.*` Postgres views. See [Two-namespace topology](/guides/two-namespace-topology/) and [Network privacy and public logic](/guides/network-privacy-and-public-logic/).

## Privacy, CUI, and using the tools

### Does anything I enter into a shipped tool leave my computer?

No. Shipped tools run in your browser with zero tracking, zero cookies, zero analytics, and a Content Security Policy (`connect-src 'self'`) that blocks outside requests. You can verify this in your browser's Network tab or by disconnecting from the internet after loading a tool. See [What happens to what you type](/guides/your-data/).

### Can I enter CUI or classified information?

Never enter classified information into any tool or Portal form. For Controlled Unclassified Information (CUI), running in a browser does not change the rules for the machine you are using—handle CUI only on systems your contract and company policy allow, or host a private copy on your own closed network. See [Run it on a closed network](/guides/closed-networks/).

### Can I trust the numbers, and what if a tool disagrees with a solicitation?

Treat tool outputs the way you treat a colleague's spreadsheet: helpful for saving time, not a substitute for verification. If a tool and a solicitation disagree, always follow the solicitation. If a tool disagrees with a published regulation, follow the regulation and propose an `✎` edit or report the citation. See [Check a tool's answer](/guides/checking-results/).

## Hosting and offline use

### Can I run my own copy of the v3.1 platform or static tools?

Yes. You can deploy the full 17-pod v3.1 platform on a single `k3s` node with one command, or host the static site and shipped tools on any web server or closed network. See [One-command quickstart](/guides/one-command-quickstart/), [Host on Kubernetes](/guides/host-on-kubernetes/), and [Host as plain files](/guides/host-static-files/).

## When something does not work

### What happens when a worker turns red or an app fails?

`cs-store` watches Pod, Deployment, and Event health and surfaces sanitized error codes (such as `E_TIMEOUT`, `E_PARSE`, or `E_NEEDS_SUBTOOL`) directly on `/guides/live-command-portal/` and `/tools/#apps`. Visitors can inspect the item trail, view `[Why?]` drawers on `/guides/workflow-state-machine/`, or propose a fix using `✎`. See [When a worker is red](/guides/when-a-worker-is-red/).

### Where else can I report a bug or request a tool?

Propose an edit directly on the Portal with `✎`, email [contact@clearedstack.com](mailto:contact@clearedstack.com), or open an issue on the [GitHub mirror](https://github.com/ClearedStack/clearedstack.com/issues). Never include real contract data or CUI in any report or public proposal.
