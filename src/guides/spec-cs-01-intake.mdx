## Overview & Role

`cs-01-intake` (`v0.1.0-draft`, owned by the `cs-01-intake` repository) is the first of ten **100% deterministic** Go workers in the `cs-workers` namespace. It replaces the conceptual Stages 1 and 2 (Discover + Record) from earlier ClearedStack designs.

With **zero AI at runtime**, `cs-01-intake` ingests candidate URLs from public government feeds, GitHub issues, scheduled web sweeps, and anonymous Portal submissions; normalizes every address through repeatable Go rules; deduplicates against existing records using **SHA-256**; and mints persistent `PA-XXXX` tracking identifiers before handing items to `cs-02-observe`.

## Interfaces & Data Contracts

- **Queue Lease Contract (`hub-queue-api`, `CONTRACT_VERSION=v1`):** Pulls work via `lease`, maintains progress with `heartbeat`, and reports outcomes via `complete`, `fail`, or `needs_subtool` over cluster-private HTTP using its Kubernetes `ServiceAccount` identity. Workers always drain priority lanes in order: `urgent` -> `normal` -> `backfill`.
- **Deterministic URL Normalization:**
  - Lowercases scheme (`https`) and hostname.
  - Strips tracking and session query parameters (`utm_*`, `ref`, `fbclid`, `gclid`, session IDs) and `#` fragments.
  - Removes redundant trailing slashes and default index filenames.
  - Enforces public-only scheme and host validation.
- **SHA-256 Deduplication & State Transitions:** Computes the SHA-256 digest of the canonical URL and checks `core.*` state via `hub-queue-api`:
  - **Existing hash:** Logs the sighting or mirror link against the existing `PA-XXXX` record without creating a duplicate.
  - **New hash:** Mints a persistent `PA-XXXX` ID (transitioning `discovered` -> `recorded`) and queues the item for `cs-02-observe`.
- **Local Spool (`/var/spool/cs`):** Stages completed intake payloads locally before acknowledging to `hub-queue-api`; if the hub is restarting, spooled results are flushed in order on recovery.

## Sub-Tools & Failure Modes

Each source adapter lives under `tools/<case>/` in the `cs-01-intake` repository (registered in `tools/registry.yaml` with `match.yaml`, deterministic Go logic, and golden test fixtures):

| Sub-Tool (`tools/<case>/`) | Source | Deterministic Responsibility |
| --- | --- | --- |
| `sam-gov` | SAM.gov public notices | Extracts public tool links, agency calculators, and attachment URLs from SAM.gov feeds. |
| `github-issues` | GitHub public mirror | Parses structured tool and paperwork suggestions opened on the public repository. |
| `web-sweep` | Public `.gov`, `.mil`, APEX, and vendor sites | Runs scheduled, `robots.txt`-respecting sweeps across public contracting resources. |
| `site-form` | `clearedstack.com` Portal | Validates and normalizes direct candidate submissions and `✎` intake proposals. |

| Failure Mode | Trigger | System Behavior & Recovery |
| --- | --- | --- |
| **Unknown source format (`E_NEEDS_SUBTOOL`)** | Input matches none of the registered `tools/<case>/` rules | **Fails closed:** pauses the item in `needs_subtool`; `cs-10-notify` opens a deduplicated task in `cs-01-intake`. Once a sub-tool + golden fixture ship via `cs-runner` and `cs-store`, `hub-queue-api` replays all paused items. |
| **Upstream timeout (`E_TIMEOUT`)** | External `.gov` feed or target URL times out | Item remains safe in the queue for deterministic retry without losing state. |
| **Malformed payload (`E_PARSE`)** | Corrupted feed entry or invalid submission schema | Worker halts that specific item cleanly and emits a sanitized `E_PARSE` fingerprint. |
| **Hub unavailable** | `hub-queue-api` restarts mid-batch | Completed intake outputs are preserved in `/var/spool/cs` and flushed automatically when connectivity returns. |

## Security & Clean-Room Boundaries

- **Zero direct database access:** `cs-01-intake` holds no Postgres credentials and cannot reach `postgres`, `cs-git`, or `cs-registry` under default-deny `NetworkPolicy` rules; all state mutations pass through `hub-queue-api`.
- **5-layer anonymous submission shield (`site-form` & Portal `✎`):** Enforces ~1s browser SHA-256 Proof-of-Work, honeypot field, daily-salted IP hash rate limiting (never storing raw IPs), strict 4 KB schema validation against `ownership_map.json` with HTML/script stripping, and owner approval in `cs-04-decide` before any edit touches `cs-git`.
- **Passive, public-only boundary:** Never creates third-party accounts, requests sales demos, bypasses paywalls or CAPTCHAs, ignores `robots.txt`, or accepts Controlled Unclassified Information (CUI) or proprietary bid figures.
- **Unprivileged pod:** Runs as non-root with dropped Linux capabilities and a read-only root filesystem (writable only at `/var/spool/cs`).
