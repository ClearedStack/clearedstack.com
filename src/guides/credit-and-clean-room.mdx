Federal procurement rules and public regulations belong to everyone, but software implementations belong to their authors. ClearedStack enforces that boundary in code through a strict clean-room architecture and the deterministic `cs-05-provenance` worker.

Every repository in the ClearedStack platform—`clearedstack.com`, all ten pipeline workers (`cs-01-intake` through `cs-10-notify`), and the cluster microservices (`cs-git`, `cs-registry`, `cs-runner`, `cs-store`)—is licensed under the **MIT License**. All Go and web code is written from scratch in a clean room, with zero copied upstream code and zero AI at runtime.

## Build, link, or skip?

ClearedStack does not exist to duplicate good open-source work. If an existing free tool runs client-side, respects privacy, and cites official public sources, rebuilding it wastes effort.

## MIT licensing and the strict clean-room wall

Every software product separates into functional ideas and copyrightable expression. ClearedStack enforces an absolute technical wall between the two.

When `cs-02-observe` inspects public pages, it extracts only structured facts and seals the raw observation snapshot behind the **clean-room wall**. Downstream build workers (`cs-06-build`) never have access to raw vendor HTML, screenshots, stylesheets, or marketing copy.

When reusable open-source libraries under permissive licenses (MIT, BSD, or Apache 2.0) are used inside a repo, all original copyright notices and upstream license files are preserved. Strong copyleft code is never mixed into ClearedStack’s MIT repositories; compliant copyleft tools are linked externally instead.

## How cs-05-provenance works

Once the owner approves a **Build** decision in `cs-04-decide`, the item moves to `cs-05-provenance` in the `cs-workers` namespace. Like every worker in the pipeline, `cs-05-provenance` is a 100% deterministic Go service—no language models, no prompt drift, and identical output on every run.

If an item requires a tool structure not yet covered by `tools/spec-profiles/`, `cs-05-provenance` fails closed, sets the state to `needs_subtool`, and opens a task via `cs-10-notify`. Once a new deterministic sub-tool and golden fixture are committed to `cs-git`, `hub-queue-api` replays the queued item automatically.

## Go-template provenance notes

Every tool inspired by an existing product carries a standardized provenance note stamped by `cs-05-provenance` using Go’s `text/template` engine. Because templates are deterministic, attribution phrasing never varies or editorializes.

<Callout kind="info" title="Standardized Go-template provenance fields">
Each rendered provenance note contains three factual lines: **Idea seen in** (`Tool Name (Vendor Name), observed YYYY-MM from its public pages`), **What we took** (`the job — one sentence describing the functional task`), and **What we did differently** (`runs entirely in your browser, free, no account; built from [Official Regulation]`).
</Callout>

Provenance notes follow four strict rules:
- They record only that a workflow was observed on a public web page on a specific date.
- They never rate, criticize, or disparage the observed product.
- They never imply partnership, sponsorship, or endorsement by the observed vendor.
- Third-party product names are used solely in a nominative sense to identify prior art.

## Compiling sanitized JSON build specs

Before `cs-06-build` can generate an isolated static tool repository, `cs-05-provenance` compiles a **sanitized JSON build spec**. This spec is the only artifact allowed to cross the clean-room wall into the build stage.

| Spec Section | What `cs-05-provenance` Includes | What Is Stripped |
|---|---|---|
| `provenance` | Rendered Go-template note, observation date, opt-out status | Raw HTML snapshots, vendor marketing URLs inside build inputs |
| `authority` | Official FAR, DFARS, NIST, or eCFR citations and effective dates | Vendor interpretations that conflict with government text |
| `schema` | Typed inputs, outputs, units, validation bounds, and formula rules | Vendor field labels, proprietary database schemas, CSS classes |
| `vectors` | Public worked examples and boundary-case assertions | Any scraped vendor test data or non-public inputs |

If an observed commercial tool produces an answer that conflicts with an official government publication, `cs-05-provenance` always encodes the official government publication. The statute is the sole source of truth.

## 48-hour and 5-day SLAs for corrections and opt-outs

`cs-05-provenance` also tracks and enforces response deadlines for vendor corrections and nominative attribution opt-outs. Requests can be submitted by emailing `contact@clearedstack.com`, opening a public GitHub issue, or submitting an anonymous `✎` edit proposal on the Portal (which routes through `cs-04-decide` for owner verification).

- **48-hour verification SLA.** Every correction or opt-out request enters a tracked clock in `cs-05-provenance` so the maintainer’s identity is verified within 48 hours.
- **5-day opt-out SLA.** When a product owner prefers not to be named, `cs-05-provenance` updates the provenance metadata to a neutral phrase (such as “a commercial product”), re-runs the Go template deterministically, and pushes the updated entry through `cs-08-catalog` within 5 days.
- **Public source integrity.** Factual errors in rules or license terms are corrected promptly upon verification, while citations to public-domain statutes and standards are never removed.
