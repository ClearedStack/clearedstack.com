Every tool in the ClearedStack catalog is a small, static, **100% deterministic** web utility built from public regulations—with zero AI at runtime, zero accounts, and zero network calls after the page loads. In ClearedStack v3.1, three workers turn an approved idea into a live listing on `/tools`: `cs-06-build`, `cs-07-verify`, and `cs-08-catalog`.

Before these three stages run, `cs-04-decide` records owner approval and `cs-05-provenance` stamps the provenance note and compiles a clean-room JSON build specification. That specification describes *what* regulatory job the tool performs without copying any third-party code, styling, or text.

## Step 1: Generate the tool with `cs-06-build`

`cs-06-build` reads the clean-room JSON specification and its worked-example fixtures, then generates an isolated, MIT-licensed static tool repository inside `cs-git`. Rather than writing custom boilerplate from scratch each time, `cs-06-build` uses four deterministic **stack templates** under `stack-templates/`:

| Stack Template | Best For | Typical Inputs & Outputs |
| --- | --- | --- |
| `calculator` | Rate build-ups, interest math, thresholds | Numeric rates or dates in; step-by-step math and cited totals out |
| `checklist` | Solicitation reviews, compliance prep | Structured yes/no items with regulatory citations and local browser progress |
| `validator` | Checking codes, tables, or local files | User-supplied text or local files parsed in memory against bundled rules |
| `decision-tree` | Eligibility, clause applicability, routing | Guided branching questions leading to a deterministic, cited outcome |

Every template produces static files—HTML, CSS, JavaScript, and bundled JSON reference tables—that run entirely in browser memory. There is no backend server, no external font or CDN link, and no runtime LLM.

If a clean-room specification requires an interaction pattern that none of the four templates support, `cs-06-build` **fails closed**: it pauses the item in `needs_subtool` so a maintainer can add a deterministic template or sub-tool rather than guessing.

## Step 2: Run the 5-condition suite with `cs-07-verify`

Once `cs-06-build` produces a tool repository, `cs-runner` builds the static bundle without Docker (using rootless BuildKit) and `cs-07-verify` runs the automated **5-condition verification suite**. A tool cannot be listed unless every check passes:

1. **Offline execution:** The tool loads once and continues working with the network completely disconnected. All lookup tables, rates, and regulatory dates ship inside the repository.
2. **Strict Content Security Policy (`connect-src 'self'`):** Every page enforces a Content Security Policy including `connect-src 'self'`, `default-src 'self'`, and `form-action 'none'`. The browser itself blocks any attempt to fetch remote assets or send data off the user's machine.
3. **Zero tracking or accounts:** Automated checks confirm there are no sign-in walls, analytics scripts, cookies, visitor counters, or third-party beacons. If a tool remembers work in browser storage, it must disclose that on the page and provide a button to clear it.
4. **Worked-example assertions:** `cs-07-verify` executes the tool against hand-calculated worked examples, edge cases (such as zero values, empty files, and date boundaries), and made-up test fixtures. Real CUI, proprietary contractor rates, and non-public solicitation text are strictly forbidden.
5. **Citations, scope limits, and MIT license:** The suite checks that every calculation cites its public source (regulation, paragraph, and revision date), states what the tool does *not* cover, includes a plain disclaimer that outputs are not legal or compliance advice, and carries an `MIT` `LICENSE` file.

## Step 3: Publish to `/tools` with `cs-08-catalog`

After `cs-07-verify` passes all five conditions, `cs-08-catalog` publishes the tool to the `clearedstack.com` catalog at `/tools`. It manages the full catalog lifecycle—adding newly verified tools, linking approved external tools, merging duplicates, or retiring outdated entries—and `cs-git` mirrors the public source code to GitHub (with zero container images stored on GitHub).

From that point on, `cs-09-monitor` watches the cited federal sources (such as eCFR, Federal Register, and NIST) for revisions, while anyone visiting `/tools` can inspect the code, run the tool offline, or propose a data or configuration fix using the anonymous `✎` edit button without signing in.
