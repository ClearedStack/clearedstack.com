## Overview & Role

`cs-07-verify` is the automated quality-assurance worker in the `cs-workers` namespace (`ownerRepo: cs-07-verify`, version `v0.1.0-draft`). Split out of the original Stage 9 (List) design, its sole responsibility is to run the deterministic **5-condition verification suite** against every static tool bundle built by `cs-runner` from a `cs-06-build` repository.

Like every worker in the pipeline, `cs-07-verify` is a 100% deterministic Go service with zero AI at runtime. A tool cannot enter the `live` catalog unless every check in the suite passes.

`cs-07-verify` runs under the Standard Kubernetes priority class so it yields cleanly if High-priority control-plane pods (`postgres`, `hub-queue-api`, `clearedstack-web`, `cs-git`, `cs-registry`, `cs-store`) need memory on a 4 GiB `k3s` node.

## Interfaces & State Transitions

`cs-07-verify` never connects directly to `postgres` or holds database credentials. It polls `hub-queue-api` over cluster-private HTTP using its Kubernetes ServiceAccount identity (`lease`, `heartbeat`, `complete`, `fail`, `needs_subtool`), always draining `urgent` before `normal` and `normal` before `backfill`.

1. **Input state (`building`):** Picks up items whose static bundle has been generated by `cs-06-build` and compiled without Docker by `cs-runner` (using rootless BuildKit).
2. **5-condition verification suite:**
   - **Offline execution:** Confirms the tool loads once and operates with the network disconnected, with all lookup tables, rates, and regulatory dates bundled inside the repository.
   - **Strict Content Security Policy:** Verifies `connect-src 'self'`, `default-src 'self'`, and `form-action 'none'` so the browser blocks any outbound data transfer or remote asset fetch.
   - **Zero tracking or accounts:** Confirms zero sign-in walls, analytics scripts, cookies, visitor counters, or third-party beacons, and verifies any local browser storage usage is disclosed with a clear-data control.
   - **Worked-example assertions:** Executes hand-calculated worked examples, boundary edge cases (zero values, empty inputs, date boundaries), and synthetic test fixtures.
   - **Citations, scope limits, and MIT license:** Checks that every calculation cites its official source (regulation, paragraph, revision date), states scope exclusions and a non-advice disclaimer, and includes an MIT `LICENSE` file.
3. **Output transition:** Stages the signed verification result in `/var/spool/cs` and reports completion to `hub-queue-api`, hand-off ready for `cs-08-catalog` to transition `building` → `live`. If regulatory ambiguity blocks verification, the item moves to `parked`.

## Sub-Tools & Failure Modes

`cs-07-verify` defines **no per-case sub-tools** (`subTools: []`) because the 5-condition verification suite is universal across all stack templates (`calculator`, `checklist`, `validator`, `decision-tree`).

| Error Code | Trigger | Pipeline Behavior |
| --- | --- | --- |
| `E_PARSE` | Missing `LICENSE`, invalid CSP policy, failed worked-example assertion, or malformed bundle | Refuses to guess; logs sanitized failure to `hub-queue-api` and halts item before catalog publication. |
| `E_TIMEOUT` | Static verification harness or fixture runner exceeds deadline | Item remains leased/retryable in `hub-queue-api`; `cs-10-notify` deduplicates repeated timeouts by fingerprint. |
| `E_NEEDS_SUBTOOL` | Unrecognized bundle or assertion format introduced by a new template | Fails closed, pauses item in `needs_subtool`, and triggers `cs-10-notify` to open a task; auto-replays once `cs-store` deploys the fix. |

## Security & Clean-Room Boundaries

- **Network isolation:** Default-deny network policies block `cs-07-verify` from reaching `postgres`, `cs-git`, or `cs-registry` directly.
- **Unprivileged execution:** Runs as non-root with dropped Linux capabilities, no privilege escalation, and a read-only root filesystem (apart from `/var/spool/cs`).
- **Clean-room & data hygiene:** Verification fixtures must use synthetic or public data only; real CUI, proprietary contractor rates, and non-public solicitation text are strictly rejected. No raw `cs-02-observe` observation artifacts ever cross into `cs-07-verify`.
- **Sanitized reporting:** `cs-store` strips internal IPs, node names, and pod hostnames before any failure status reaches `pub.*` or `/tools/#apps`.
