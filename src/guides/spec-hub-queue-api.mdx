`hub-queue-api` (`v0.1.0-draft`, owned by `clearedstack.com`) is the sole read-write gatekeeper in front of `postgres`. It coordinates all 10 deterministic workers in `cs-workers`, streams live status to `clearedstack-web` over Server-Sent Events (SSE), and protects anonymous edit intake with a 5-layer anti-spam shield.

## Overview & Role

Rather than letting 10 worker pods hold database passwords or implement their own locking, `hub-queue-api` centralizes all state transitions and queue coordination:

- **Sole `core.*` Writer:** Besides `postgres` itself, `hub-queue-api` is the only service in the cluster with read/write access to `core.*` tables.
- **Lease & Heartbeat Coordinator:** Issues work leases in priority order (`urgent` -> `normal` -> `backfill`), tracks worker heartbeats, and commits state changes alongside the next queue step in a single Postgres transaction.
- **`needs_subtool` Pause & Replay:** Places items encountering unknown layouts into `needs_subtool` and automatically replays them once `cs-store` deploys the updated worker digest.
- **SSE Live Feed:** Publishes real-time queue depths, worker health, and edit status transitions to `clearedstack-web`.
- **5-Layer Anti-Spam Edit Intake:** Screens anonymous `✎ Edit` submissions before they enter `cs-04-decide` as `pending_approval`.

## Interfaces & Data Contracts

| Peer Service | Direction | Protocol / Auth | Data Contract |
| --- | --- | --- | --- |
| **`postgres`** | Outbound | SQL (read/write on `core.*`) | Atomic transactions for item state, queue leases, edit proposals, and append-only ledger |
| **`cs-workers` (`cs-01`..`cs-10`)** | Inbound | Cluster-private HTTP (Kubernetes ServiceAccount) | Lease acquisition (`urgent`/`normal`/`backfill`), heartbeats, result submission, and `E_NEEDS_SUBTOOL` reporting |
| **`clearedstack-web`** | Outbound / Inbound | Cluster-private HTTP + SSE | Streams live SSE progress; receives anonymous `✎ Edit` proposals |
| **`cs-store`** | Inbound | Cluster-private HTTP | Receives sanitized pod health and stripped error events (zero node names or internal IPs) |

### 5-Layer Anti-Spam Edit Intake

Every anonymous `✎ Edit` submission must pass all five layers before reaching `cs-04-decide`:

1. **Browser Proof-of-Work:** Validates the ~1-second client-side cryptographic puzzle token.
2. **Honeypot Field:** Silently discards requests where the hidden form field is populated.
3. **Daily-Salted IP Rate Limit:** Hashes the client IP with a daily-rotating secret salt and caps submissions per hash without ever storing raw IP addresses.
4. **Strict Schema Check:** Verifies the target exists in `ownership_map.json`, enforces a 4 KB payload limit, and strips all HTML and scripts.
5. **Review Gate:** Holds every valid proposal in `pending_approval` inside `cs-04-decide` until explicitly approved by the human owner.

## Failure Modes & Recovery

- **Hub Restart During Worker Execution:** Because `hub-queue-api` is a single control-plane pod, a rolling upgrade or restart makes it briefly unreachable. Workers stage completed outputs in their **local spool volume** first, then retry delivery to `hub-queue-api` on a short backoff until acknowledged, deleting the spooled file only after Postgres confirms receipt.
- **Worker Crash Mid-Lease:** If a worker pod dies before acknowledging a task, its lease expires in `postgres` and `hub-queue-api` re-leases the unfinished item to a healthy worker.
- **SSE Disconnect or Stale Feed:** If the SSE stream to `clearedstack-web` stalls for more than 15 seconds, deterministic attention rules surface a P1 warning on the Command Portal.
- **High-Load Contention:** High Priority Class keeps `hub-queue-api` scheduled ahead of workers and ephemeral Jobs when node memory tightens.

## Security & Clean-Room Boundaries

- **Zero DB Credentials in Workers:** Workers in `cs-workers` authenticate via Kubernetes ServiceAccount HTTP; they never hold Postgres passwords and have no knowledge of `core.*` table layouts.
- **No Public Ingress:** Blocked from direct internet access by default-deny `NetworkPolicy`; only `clearedstack-web` forwards sanitized intake requests.
- **No Automatic Cluster Writes from Public Edits:** Anonymous proposals cannot touch `cs-git` or running pods; they remain isolated in `pending_approval` until owner approval.
- **Unprivileged Execution:** Runs as non-root with dropped Linux capabilities and no privilege escalation.
