The catalog grows in two ways: someone asks for a tool, or someone builds one.

## Request a tool

Email [contact@clearedstack.com](mailto:contact@clearedstack.com) or [open an issue on GitHub](https://github.com/ClearedStack/clearedstack.com/issues). A useful request covers three things:

- **The job**: what you need to produce, and what you do by hand today.
- **Who needs it**: for example, a solo developer pricing a first bid.
- **The public source**: the regulation, standard or guide the tool would be based on, with a link if you have one.

Asking for a tool that is already on the list as Planned helps too. It shows which ones to build first.

## Add a tool you built

Tools live in their own repositories. To be listed here, a tool has to be:

1. **Free and open source**, with no paid tier and no ads.
2. **Client-side**. It does not send what the user enters to any server.
3. **Free of tracking**: no analytics, third-party scripts or accounts.
4. **Built from public sources**, and clear about which ones.
5. **Honest about its limits**, including that its output is not professional advice.

To list it, add one entry to the catalog file in this site’s repository and open a pull request. The [contributing guide](https://github.com/ClearedStack/clearedstack.com/blob/main/CONTRIBUTING.md) shows the entry format.

## What never goes in

Do not put classified information, CUI, export-controlled data or real contract data in a request, an issue, a tool or its test data. “Public” means officially released. A document that leaked is not public for this project.
