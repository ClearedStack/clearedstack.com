`clearedstack-web` (`v0.2.0-draft`, owned by `clearedstack.com`) is the public-facing web application in the `clearedstack` control-plane namespace. It serves the contractor-first tool catalog, operational Command Portal, App Store UI, and anonymous `✎ Edit` intake without requiring user accounts or logins.

## Overview & Role

`clearedstack-web` is the **only pod in the entire 17-pod cluster exposed to the public internet** via the Kubernetes Ingress. Its responsibilities are strictly presentation, read-only public data rendering, and client-side intake framing:

- **Command Portal & Catalog:** Serves the unified tool catalog (`/tools/`), operational guides (`/guides/`), live P0–P2 attention feed, and App Store UI.
- **Zero Login Lock:** All browsing, queue inspection, sanitized error viewing, and edit proposals work anonymously without accounts, passwords, or OAuth redirects.
- **Sanitized Read-Only Queries:** Reads exclusively from sanitized `pub.*` views in `postgres`—never touching `core.*` internal tables or cluster secrets.
- **Anonymous Edit Intake UI:** Uses `ownership_map.json` to map any editable element on the page to its owning repository (`clearedstack.com` or `cs-01`..`cs-10`) and change class (`DATA`, `CONFIG`, or `ISSUE`), then forwards proposals to `hub-queue-api`.

## Runtime & Resource Budget

| Attribute | Value |
| --- | --- |
| **Namespace** | `clearedstack` (Control Plane) |
| **Kind** | `control-plane` |
| **Version** | `v0.2.0-draft` |
| **Owning Repo** | `clearedstack.com` |
| **RAM Request** | `128 MiB` |
| **Priority Class** | High (Control Plane — protected from eviction) |
| **Storage** | Stateless (no Persistent Volume Claim) |
| **Network Exposure** | Public Ingress (`HTTP/HTTPS`); cluster-private egress to `postgres` (`pub.*`) and `hub-queue-api` |

Because `clearedstack-web` holds no local persistent state, Kubernetes can restart or replace the pod at any time without data loss.

## Interfaces & Data Contracts

`clearedstack-web` sits at the edge of the `clearedstack` namespace and communicates with two internal control-plane services:

| Peer Service | Direction | Protocol / Role | Data Contract |
| --- | --- | --- | --- |
| **Cluster Ingress** | Inbound | HTTPS (Public) | Serves static/SSR Portal pages, `/tools/`, `/guides/`, and anonymous `✎ Edit` forms |
| **`postgres`** | Outbound | SQL (`pub_ro` role) | Read-only `SELECT` access to sanitized `pub.*` views only; zero access to `core.*` |
| **`hub-queue-api`** | Bidirectional | Cluster-private HTTP + SSE | Subscribes to Server-Sent Events (SSE) for live queue/status updates; submits `✎ Edit` payloads (with ~1s browser Proof-of-Work token and honeypot field) |

### Live Edit Status Tracking

After a visitor submits an anonymous edit, `clearedstack-web` turns the element's `✎ Edit` button into a live status pill backed by `hub-queue-api` SSE events:

1. **Proposed:** Passed 5-layer anti-spam and `ownership_map.json` schema checks; waiting in `cs-04-decide`.
2. **Approved:** Approved by the owner and routed via `cs-10-notify` to `cs-git`.
3. **Building:** `cs-runner` is running deterministic tests and packaging the updated image.
4. **Live:** `cs-store` reconciled the new digest and the updated content is live.

## Failure Modes & Recovery

- **Pod Crash or OOMKill:** Because `clearedstack-web` is stateless with no PVC, `k3s` restarts the pod automatically. High Priority Class protects it from preemption during `cs-runner` builds or `cs-02-observe` headless browser Jobs.
- **`hub-queue-api` Unavailable / SSE Drop:** If `hub-queue-api` restarts during a rolling upgrade, the SSE stream drops and the UI surfaces a stale-feed indicator (P1 attention triggers if the live feed is stale for more than 15 seconds) while `pub.*` views remain readable from `postgres`.
- **`postgres` Unavailable:** Public pages that depend on `pub.*` views degrade gracefully until `postgres` recovers; no write state is lost because `clearedstack-web` never writes to the database.

## Security & Clean-Room Boundaries

- **Only Public Door:** Default-deny `NetworkPolicy` blocks Ingress traffic to every other pod in `clearedstack` and `cs-workers`.
- **Database Isolation:** Connects to `postgres` solely with the `pub_ro` role, which has zero privileges on `core.*` tables, credentials, or internal operational state.
- **No Topology Leakage:** Never receives raw node names, pod hostnames, or internal cluster IPs; `cs-store` strips those fields before status reaches `hub-queue-api` and `pub.*`.
- **Unprivileged Execution:** Runs as a non-root user with dropped Linux capabilities, no privilege escalation, and a read-only root filesystem where state does not need to be written.
- **Anti-Spam Framing:** Enforces client-side Proof-of-Work (~1s cryptographic puzzle) and a hidden honeypot field before forwarding anonymous edit proposals to `hub-queue-api`.
