The short answer is that everything you type into a shipped tool stays on your computer, and everything on the public Portal is sanitized before it ever leaves the cluster. This guide explains how both halves work in ClearedStack v3.1, where the limits are, and how to check them yourself.

## Shipped tools run locally in your browser

Most web applications collect what you type, send it to a server, and return an answer. Your information leaves your machine before you see a result.

Every shipped ClearedStack tool has only the local half. When you open a tool, your browser downloads the static page and its compiled JavaScript once. After that, all arithmetic, text parsing, and file reading happen on your workstation. There is no backend server waiting for your input, no login, no analytics, and zero network calls.

Every page and shipped tool enforces a Content Security Policy with `connect-src 'self'`. That instruction tells your browser to block any outbound network request, third-party API call, or form submission to another server. If a line of code tried to send your numbers elsewhere, your browser would refuse.

## Zero AI at runtime

Neither the shipped tools nor the 10 platform workers (`cs-01` through `cs-10`) run artificial intelligence models at runtime. Calculations, parsers, and pipeline rules are 100% deterministic code that you can inspect in each MIT-licensed repository.

AI tools (Claude Code and Antigravity) are used only during development to help the human maintainer draft code, documentation, and tests. Every formula and rule is verified by a person against official regulations before release. See [How AI is used to build this project](/guides/built-with-ai/).

## What the public Portal exposes (`pub.*` views)

ClearedStack v3.1 has a single public door: the `clearedstack-web` Portal at `clearedstack.com`. Everything running in the cluster is visible there without signing in—live app and worker health, queue depths, item trails, and sanitized error codes such as `E_TIMEOUT`, `E_PARSE`, or `E_NEEDS_SUBTOOL`.

Internal infrastructure stays strictly cluster-private. The Portal queries Postgres only through read-only `pub.*` views under the `pub_ro` database role, and `cs-store` strips node, pod, and network metadata before reporting status. The following never appear in `pub.*` views or on the Portal:

- internal cluster IPs, node names, pod hostnames, and `.svc.cluster.local` addresses
- `NetworkPolicy` rules and Ingress internals
- database passwords, ServiceAccount tokens, GitHub push tokens, signing keys, and the daily IP salt

## Anonymous edits use daily-salted IP hashes

Anyone can propose an edit anywhere on the Portal using the `✎` button without creating an account. To stop spam and automated abuse without storing personal data or requiring a login, submissions pass through a five-layer shield:

1. **Browser Proof-of-Work:** your browser solves a ~1-second SHA-256 puzzle on submit.
2. **Honeypot field:** a hidden input silently discards automated scraper submissions.
3. **Daily-salted IP hash rate limit:** the Portal hashes your IP address with a secret salt that rotates daily to enforce rate limits. Raw IP addresses are never stored in the database.
4. **Strict schema validation:** `ownership_map.json` checks the target element, edit class (`DATA`, `CONFIG`, or `ISSUE`), and 4 KB maximum size, stripping all HTML and scripts.
5. **Human approval gate:** accepted proposals sit in `core.edit_proposal` as `pending_approval` and never touch `cs-git` or the cluster until the owner approves them in `cs-04-decide`.

## Check it yourself

You can confirm that a shipped tool makes zero network calls in about a minute using made-up numbers:

1. Open the tool and open your browser’s developer tools (`F12` on Windows or Linux, `Command-Option-I` on Mac).
2. Select the **Network** tab and click the clear button.
3. Type numbers, paste text, or load a file, then watch the list.

A compliant tool adds nothing to the Network tab while you work. You can also right-click any page, choose **View Page Source**, and search for `Content-Security-Policy` to confirm `connect-src 'self'` is present.

Load any shipped tool, then disconnect from the network by turning off Wi-Fi or unplugging the cable. Keep using the tool. If it still computes answers, all work is happening locally on your computer.
</Callout>

## What a web server and your screen can still see

To send you a webpage, the host serving `clearedstack.com` sees standard HTTP request metadata: your IP address, the page requested, the timestamp, and your browser user agent. Nothing you type into a local tool is part of that request.

Keeping data off a server also does not protect your screen locally. Browser extensions, employer endpoint monitoring, clipboard managers, screen sharing, and built-in browser translation or AI assistant features can all read what is on your screen. Use a clean browser profile or private window for sensitive work, and clear browser storage when using a shared computer.

## What never to enter

- **Classified information:** never enter it into any tool, browser, or form.
- **Controlled Unclassified Information (CUI) and real contract rates:** never enter CUI, export-controlled technical data, or real contract rates into public Portal forms (such as `✎` edit proposals, which are public by design) or into AI prompts. For local shipped tools, remember that running in a browser does not change the rules for the workstation you sit at—handle CUI and proprietary rates only on systems your contract and company policy allow, or host a copy inside your own network.
- **Unsure how a tool behaves?** Test it with made-up numbers first.

## If you find a tool that breaks the rule

Stop using it and report it. Email [contact@clearedstack.com](mailto:contact@clearedstack.com) or open an issue in the tool’s repository with the request address you saw in the Network tab. Any tool that sends user input over the network is removed from the catalog until it is fixed.
