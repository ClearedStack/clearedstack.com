ClearedStack builds, tests, and runs every component on a single lightweight `k3s` cluster using `containerd`, with zero Docker anywhere on the host. Two clean-room MIT Go microservices handle the entire journey from a code push to a live, monitored app: `cs-runner` (32 MiB RAM) and `cs-store` (48 MiB RAM).

## Ephemeral build Jobs with cs-runner

When `cs-git` receives a commit on `main` or a tag, it sends a push webhook to `cs-runner` in the `clearedstack` namespace. Rather than keeping an always-on CI runner pool or a privileged Docker daemon, `cs-runner` spawns short-lived Kubernetes `Job` pods (`ko` for Go services and workers; rootless BuildKit for `clearedstack-web`), runs the repository's deterministic golden test suite, signs passing images with `cosign`, pushes them to `cs-registry`, and writes the new immutable digest back to `app.yaml` in `cs-git` with a `[skip-ci]` marker. (See [Internal OCI Registry and No-Docker Builds](/guides/cs-registry-and-no-docker/) for the full OCI storage and 5-digest retention breakdown.)

## Replacing Argo CD and CasaOS with cs-store

Once an image digest is recorded in `app.yaml`, `cs-store` takes over. Traditional GitOps controllers like Argo CD introduce custom resource definitions (CRDs) and complex sync controllers, while home-server dashboards like CasaOS expect Docker Compose. `cs-store` combines the best parts of both into a single 48 MiB Go binary that speaks native Kubernetes Server-Side Apply—no custom CRDs required.

`cs-store` watches `app.yaml` files in `cs-git` alongside image digests in `cs-registry`, then manages deployments across the platform's two namespaces: `clearedstack` for the seven control-plane pods and `cs-workers` for the ten deterministic workers.

Through the `/guides/apps/` App Store view (and `/tools/#apps` catalog section) on `clearedstack.com`, the owner gets four 1-click lifecycle controls backed by `cs-store`:

- **Install:** Applies the app's manifests into the target namespace for the first time.
- **Upgrade:** Rolls the Deployment forward to the latest signed digest built by `cs-runner`.
- **Pause:** Scales the workload down cleanly without deleting its configuration or data.
- **Rollback:** Switches `app.yaml` and the live Deployment back to one of the previous digests retained in `cs-registry`.

## Live health and sanitized error reporting

`cs-store` continuously watches Kubernetes Pods, Deployments, and Events so `/guides/apps/` and `/tools/#apps` reflect what is actually running. Before sending any status update to `hub-queue-api` for display on the public Portal, `cs-store` strips out internal cluster IP addresses, node names, and pod hostnames. Visitors see clear health states and standardized error codes—such as `E_TIMEOUT`, `E_PARSE`, or `E_NEEDS_SUBTOOL`—while the cluster's internal network layout stays completely private.
