Every repository in ClearedStack—the Portal (`clearedstack.com`), all ten pipeline workers (`cs-01` through `cs-10`), and the four platform services (`cs-git`, `cs-registry`, `cs-runner`, and `cs-store`)—is published under the **MIT license** and written from scratch. In software engineering, a **clean-room rewrite** means studying what a tool needs to accomplish and building a fresh implementation from zero, without copying any source code, templates, or assets from existing projects.

ClearedStack applies this clean-room rule in two places: first, in how we build our own lightweight Kubernetes platform services, and second, in how our automated pipeline turns public observations into independent compliance tools.

## Why we rewrote the platform services in Go

Self-hosted developer platforms usually stitch together large upstream projects such as Forgejo for Git, Harbor or GitHub Container Registry for images, Argo CD for Kubernetes sync, and CasaOS for app management. Those tools are powerful, but they carry heavy memory footprints, complex databases, and upstream license obligations that ClearedStack does not need.

Instead of bundling them, ClearedStack runs four focused, clean-room Go microservices inside the cluster-private `clearedstack` namespace. They borrow the best *ideas* from Forgejo, Argo CD, and CasaOS—such as simple app cards and Git-driven deployments—without copying a single line of upstream code.

| Upstream Inspiration | Clean-Room Service | What It Does | RAM Requested |
| --- | --- | --- | --- |
| **Forgejo** | **`cs-git`** | Stores bare Git repositories on a cluster disk, handles push webhooks, and mirrors commits to GitHub. | 64 MiB |
| **GHCR / Harbor** | **`cs-registry`** | Runs an internal-only OCI v2 container image store, keeps the last 5 image digests for instant rollback, and cleans old layers daily. | 64 MiB |
| **Forgejo Actions** | **`cs-runner`** | Listens for `cs-git` push webhooks, runs Docker-free build jobs (`ko` for Go, rootless BuildKit for web), signs images, and updates `app.yaml`. | 32 MiB |
| **Argo CD + CasaOS** | **`cs-store`** | Reads `app.yaml` from `cs-git`, provides 1-click Install, Upgrade, Pause, and Rollback via Kubernetes Server-Side Apply, and reports sanitized health to the Portal. | 48 MiB |

Because each service does only what ClearedStack needs, all four platform services together request just 208 MiB of memory. Combined with the Portal, Postgres, and all ten deterministic workers, the entire 17-pod platform fits comfortably on a single 4 GiB `k3s` node.

## Avoiding license baggage and hidden complexity

Upstream projects often mix licenses across hundreds of dependencies, or use copyleft licenses that restrict how code can be combined and redistributed. Writing `cs-git`, `cs-registry`, `cs-runner`, and `cs-store` from scratch in Go under the MIT license keeps the entire stack legally simple and uniform. Anyone can read, fork, or reuse any part of ClearedStack without navigating conflicting license terms.

This approach also removes operational surprises. There are no custom Kubernetes Custom Resource Definitions (CRDs) to maintain, no background user-account databases inside the Git server, and no container images pushed to third-party registries. Source code is mirrored publicly to GitHub on every change, while built images stay inside `cs-registry`.

## The second clean-room wall: `cs-02-observe` to `cs-06-build`

The same clean-room discipline governs how ClearedStack builds compliance tools inside its ten-worker pipeline. Observing an existing public tool or agency page is useful for understanding what problem contractors face, but raw page text, HTML layouts, and vendor designs are copyrightable expression.

To protect creators and keep every generated tool legally independent, ClearedStack places a strict clean-room wall between **`cs-02-observe`** (which reads public surfaces) and **`cs-06-build`** (which generates new static tools).

| Pipeline Stage | What It Sees | Clean-Room Boundary |
| --- | --- | --- |
| **`cs-02-observe`** | Public web pages, DOM tables, and agency PDFs | Extracts structured facts into strict JSON and seals the raw snapshot behind the clean-room wall. |
| **`cs-03-evaluate` & `cs-04-decide`** | Structured evaluation scores and owner determinations | Decides whether to link an existing free tool or approve a clean-room build. |
| **`cs-05-provenance`** | Official regulatory rules and worked examples | Compiles a clean-room JSON build specification with provenance notes and zero vendor copy. |
| **`cs-06-build`** | Only the clean-room JSON spec and deterministic stack templates | Generates an isolated, offline-capable static tool without ever seeing raw HTML or competitor code. |

By separating observation from generation, `cs-06-build` can never accidentally echo a third-party layout, phrasing, or script. Together, the MIT-licensed Go platform services and the `cs-02-observe`-to-`cs-06-build` pipeline wall ensure that everything ClearedStack runs and ships is small, deterministic, transparent, and built cleanly from the ground up.
