In ClearedStack v3.1, evaluating candidate tools and approving changes is split between two focused Go services in the `cs-workers` namespace: `cs-03-evaluate` (which scores candidates with zero AI) and `cs-04-decide` (which powers the human owner's `/guides/ownership-map-and-edit-loop/` inbox). Every rule, weight, and decision outcome is visible to the public through read-only `pub.*` database views on the Portal—no sign-in required.

## Deterministic evaluation with cs-03-evaluate

`cs-03-evaluate` leases `observed` items from `hub-queue-api` and runs a 100% deterministic YAML/Go rule engine. Given the same observed facts, it produces the exact same score on any cluster, with zero language-model calls or token costs.

To handle differences across contracting domains without guesswork, `cs-03-evaluate` uses category-specific sub-tools under `tools/rubric-profiles/<category>/` (such as `pricing`, `proposal`, `cyber`, `market`, or `devsecops`). Each profile defines domain-specific thresholds and golden test fixtures. If an item arrives with an unsupported category, the worker **fails closed**: it pauses the item in `needs_subtool` and `cs-10-notify` opens a task in the `cs-03-evaluate` repository. Once a new profile is added and built by `cs-runner`, `hub-queue-api` automatically replays the paused item.

## The five knockout gates

Before any points are tallied, `cs-03-evaluate` checks five binary gates. Failing any single gate stops evaluation immediately and moves the item to `screened-out` with the failure reason logged publicly.

1. **Public source.** Rules, formulas, and thresholds must come from officially released public materials (statutes, FAR, DFARS, or NIST Special Publications)—never paywalled manuals or unwritten industry folklore.
2. **Runs in the browser.** The tool must execute entirely client-side using HTML, CSS, JavaScript, or WebAssembly, with no backend server or remote API.
3. **Private by design.** The tool must work offline, require no accounts, emit zero tracking telemetry, and enforce a strict Content Security Policy (`connect-src 'self'`).
4. **One job.** The tool must perform a single, focused task describable in one active sentence starting with a verb. Oversized suites fail this gate unless split into smaller proposals.
5. **Arithmetic, not advice.** The tool must compute numbers, structure data, or look up citations—never render legal advice or replace a contracting officer's discretion.

## The 100-point rubric

Candidates that pass all five gates are scored across seven weighted factors. Each factor receives an integer rating from `1` to `5`, multiplied by its weight for a composite score between `20` and `100`.

| Factor | Weight | Score 1 (Low) | Score 3 (Mid) | Score 5 (High) |
| --- | --- | --- | --- | --- |
| Need for small businesses | 20 pts (×4) | Rare edge case; minimal time spent. | Occasional requirement (such as annual reporting). | Universal recurring blocker for small contractors; high manual friction or penalty if miscalculated. |
| Gap: no free, private option exists | 20 pts (×4) | Multiple high-quality, free, client-side tools already exist. | Government provides a clunky portal, or open tools exist with poor usability. | Only predatory paywalled SaaS or lead-generation traps exist; zero free tools available. |
| Strength of the public source | 15 pts (×3) | Informal agency slide deck or ambiguous draft. | Agency policy memo or fluctuating interim rule. | Codified statute, enacted Federal Regulation (FAR/DFARS), or ratified NIST standard. |
| Fits in a browser | 15 pts (×3) | Demands heavy multi-megabyte datasets or compute near browser memory limits. | Requires moderate bundled lookup tables (< 2 MB) or specialized parser. | Lightweight, pure mathematical or string transform (< 50 KB data, zero complex dependencies). |
| Small enough to read | 10 pts (×2) | Sprawling state machine with extensive configuration. | Moderate configuration with well-defined inputs and outputs. | Concise input-to-output function readable in one sitting (< 300 lines of core logic). |
| Can be checked (worked examples exist) | 10 pts (×2) | Highly subjective interpretation; high audit exposure if misapplied. | Mathematical formula with edge cases requiring prominent disclaimers. | Fully deterministic arithmetic with official government test vectors available to verify results. |
| Low upkeep of reference data | 10 pts (×2) | Requires frequent data updates or fragile web scraping. | Annual update schedule (such as fiscal year rate tables). | Static statutory logic; zero periodic data maintenance unless regulation is amended. |

Based on the composite score and deterministic override rules, `cs-03-evaluate` assigns a preliminary recommendation and moves the item to `scored`:

- **Build (Score ≥ 75 and Gap > 1):** Recommended for clean-room implementation.
- **Link (Score ≥ 75 and Gap = 1):** Override—an acceptable free, private tool already exists, so ClearedStack links to it rather than rebuilding.
- **Park (Score 55–74):** Valid idea deferred due to missing public data, pending rulemaking, or capacity.
- **Reject (Score < 55):** Below the inclusion threshold, logged publicly with its point breakdown.

If a candidate scores `4` or `5` on **Need** but `1` or `2` on **Small enough to read**, the engine flags it for **split/merge review** so the owner can break it into atomic single-job tools.

## Five deterministic tie-breakers

When multiple `scored` candidates share the exact same composite score, `cs-03-evaluate` breaks ties in a fixed five-step order:

1. **Roadmap phase fit** — Direct alignment with the active project phase wins.
2. **Gap severity** — Higher score on the Gap factor wins.
3. **Low upkeep** — Higher score on the Low upkeep factor wins.
4. **Small code footprint** — Higher score on the Small enough to read factor wins.
5. **Community demand** — Higher count of independent requests and issue upvotes wins.

## Human decisions and accountability (`cs-04-decide`)

`cs-04-decide` has no `tools/<case>/` sub-tools because final judgment belongs strictly to the human project owner. It powers the [Decisions & Public Edits](/guides/ownership-map-and-edit-loop/) queue on `clearedstack.com`, which handles two queues:

- **Tool determinations:** The owner reviews `scored` (or overridden `screened-out`) candidates and chooses **Approve (Build)**, **Link**, **Merge**, **Park**, **Reject**, or **Override**. Any override requires an explicit written reason, which is recorded in the public decision log. Approved items advance to `cs-05-provenance` (`approved` state).
- **Anonymous public edit approvals:** Any visitor can click `✎` anywhere on the Portal to propose a `DATA`, `CONFIG`, or `ISSUE` edit without signing in. After passing browser Proof-of-Work, a honeypot check, daily-salted IP hash rate limits, and `ownership_map.json` schema validation, proposals wait in `core.edit_proposal` (`pending_approval`). Nothing touches `cs-git` or the cluster until the owner clicks **Approve**, which dispatches `cs-10-notify` on the `urgent` lane (`Proposed -> Approved -> Building -> Live`).
