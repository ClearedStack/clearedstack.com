This website, its guides, and its supporting code are drafted with the help of artificial intelligence tools—specifically Claude Code by Anthropic and Antigravity by Google. Every line of code, prose, and regulatory reference is reviewed, verified, and merged by a single human project owner, who decides what gets built and remains solely accountable for everything published here.

Just as important is where AI is **not** used. There is a strict wall between how ClearedStack is written and how ClearedStack runs. **Zero AI runs at runtime** anywhere in the platform: not in the 10 pipeline workers (`cs-01-intake` through `cs-10-notify`), not in the Portal (`clearedstack.com`), and not in any shipped tool. Every runtime step is 100% deterministic, meaning the same input always produces the exact same output with no language models, no machine learning APIs, and no token costs.

## Authoring time vs. runtime

ClearedStack treats AI assistants as drafting and research aids, never as autonomous operators or runtime engines.

| Stage | Who or What Runs | How It Works |
|---|---|---|
| **Authoring time** | Human owner + AI tools (Claude Code, Antigravity) | AI drafts TypeScript, Go, Markdown guides, and test cases under human direction. |
| **Verification gate** | Human owner only | Owner checks every citation against official sources, audits math by hand, and signs commits. |
| **Platform runtime** | Control plane + 10 Go workers (`cs-01`..`cs-10`) | 100% deterministic rules, extractors, and templates. Zero LLMs and zero AI calls. |
| **Shipped tools** | Static browser tools (JavaScript / WebAssembly) | Runs offline in your browser with `connect-src 'self'`, zero tracking, and zero external requests. |

## Why the 10 workers stay 100% deterministic

Many software pipelines reach for an AI model whenever they encounter an unfamiliar web page, an awkward PDF table, or a messy edge case. ClearedStack takes the opposite approach. All 10 workers—from `cs-01-intake` (deduplication) and `cs-02-observe` (page extraction) through `cs-03-evaluate` (rubric scoring), `cs-06-build` (tool generation), and `cs-07-verify` (automated testing)—execute plain, deterministic Go code and explicit rules.

When a worker hits an unknown layout it cannot parse cleanly, it **fails closed**. Instead of guessing with an AI model, the worker pauses that item in a `needs_subtool` state and logs a task in the worker's repository. During authoring time, a new deterministic sub-tool (stored under `tools/<case>/` with golden test fixtures) is written, reviewed by the owner, and deployed. Once deployed, the queue automatically replays the paused items. Every solved edge case becomes permanent, repeatable code rather than a probabilistic guess.

## The human review rule and known AI failure modes

Language models are useful for drafting, but they fail in predictable ways—especially in federal contracting, where a wrong clause number or outdated threshold can cause real compliance issues. Every AI-assisted draft is checked against three known failure modes before it can be merged:

| AI Failure Mode | What Goes Wrong | Human Verification Gate |
|---|---|---|
| **Invented citations** | Models hallucinate plausible-looking FAR or DFARS clause numbers that do not exist. | Every citation is verified directly against primary official sources (eCFR, Acquisition.gov, GovInfo, NIST). |
| **Outdated rules** | Models cite repealed provisions, old dollar thresholds, or superseded NIST revisions. | Current effective dates and active statutory text are confirmed before approval. |
| **Confident wrong math** | Models explain formulas clearly while making rounding or boundary-case errors. | Calculations are checked by hand across normal and edge cases, backed by deterministic test suites. |

## What never goes into an AI prompt

We do not make claims about how external AI vendors handle data behind the scenes. Instead, this project follows a zero-trust prompt policy: sensitive, proprietary, or non-public information is never entered into an AI tool in the first place.

| Data Category | Policy | Examples |
|---|---|---|
| **CUI, classified, or non-public government data** | Strictly banned | Defense technical data, draft solicitations, source selection information |
| **Real company financials or rates** | Strictly banned | Actual labor rates, indirect pools, live bids, proprietary pricing |
| **Personal or active contract data** | Strictly banned | Individual names, private emails, real contract numbers |
| **Public rules and synthetic examples** | Permitted | Enacted FAR/DFARS text, public NIST standards, fictional data such as `$50.00/hr` or `FA0000-00-C-0000` |

## Transparency and reporting mistakes

To keep version history transparent, commits drafted with AI assistance include an `Assisted-by` trailer naming the tool alongside the human owner's sign-off, and all source code is mirrored publicly from `cs-git` to GitHub.

If you spot an incorrect citation, a misquoted rule, or a calculation error anywhere on ClearedStack, you can propose an edit directly on the Portal without signing in, open an issue on the [ClearedStack GitHub repository](https://github.com/ClearedStack/clearedstack.com/issues), or email [contact@clearedstack.com](mailto:contact@clearedstack.com) with the page URL and supporting official source.
