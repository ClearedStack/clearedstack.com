Observation is Stage 3 of the prior-art engine. Once a tool or spreadsheet is identified and assigned a record ID, an observer audits its public interface to understand what problem it solves, what data it handles, and whether it could be rebuilt as an independent, client-side tool.

The observation protocol is strictly passive and public. Observers read public documentation and examine network traffic during calculations. They never create accounts, start trials, or enter real contracting data.

To see how observation fits into the full evaluation process, visit [How we decide](/how-we-decide/).

## The observation checklist

When an observer inspects a candidate, they follow a standardized sequence of checks to collect objective evidence.

<Flow
  caption="The observation checklist, from scope inspection to confidence grading"
  steps={[
    { label: "Check access", detail: "Verify that the tool is accessible on the open web without accounts or trials." },
    { label: "Audit network traffic", detail: "Use browser Developer Tools to see whether calculations send data to a server." },
    { label: "Run offline test", detail: "Disconnect from the network and verify whether the tool can run locally." },
    { label: "Verify citations", detail: "Look up cited regulations on official government portals to confirm published rules." },
    { label: "Archive snapshot", detail: "Submit the URL to an immutable web archive so findings remain permanent." },
    { label: "Grade confidence", detail: "Classify findings into Seen, Stated, or Unknown based on verified evidence." },
  ]}
/>

1. **Check access**: Determine whether the tool is freely usable on the public web or restricted behind gates.
2. **Audit network traffic**: Monitor the browser’s Network tab during test calculations to determine whether user inputs remain local or are transmitted to remote endpoints.
3. **Run offline test**: Load the page, sever network connectivity (such as by turning off Wi-Fi), and run calculations to test for server dependencies.
4. **Verify citations**: Extract the legal authorities or standard clauses cited by the tool and cross-reference them against official government websites.
5. **Archive snapshot**: Submit the public URL to a permanent web archive (such as the Wayback Machine) so the exact page observed can be reviewed at any time.
6. **Grade confidence**: Record every observation field alongside an explicit confidence tier (Seen, Stated, or Unknown).

## The access boundary

The strictest rule of observation is that observers never bypass access controls or create credentials. If a tool requires an account, observation stops at the public surface.

If a tool requires a corporate sales demonstration, a paid license, or a personal email address to view results, the observer records the vendor’s public marketing claims and marks them as unverified. The project never initiates sales calls or accepts commercial terms of service to evaluate software.

## What gets recorded

Every observed tool is documented in a structured record with verifiable evidence:

- **The job**: A single sentence starting with an active verb describing the core task (for example, “Calculate fringe and overhead rates from cost pools”).
- **Inputs**: The specific parameters, file formats, and data fields accepted.
- **Outputs**: The reports, numbers, tables, or export files generated.
- **Login requirement**: Whether the tool requires an account, offers optional login, or requires zero authentication.
- **Tracking profile**: Third-party telemetry scripts, analytics beacons, tracking cookies, and content security policy headers seen on the page.
- **License or copyright**: The declared intellectual property terms, such as an open-source license, public domain notice, or proprietary copyright statement.
- **Price model**: Free public utility, freemium, paid subscription, or custom enterprise quote.
- **Public rule cited**: The official standard, regulation, or procurement clause cited, including section numbers and official links.
- **Date observed**: The ISO date (`YYYY-MM`) when the observation was conducted. Observations older than twelve months are marked stale and re-checked before making build decisions.
- **Archived snapshot link**: A permanent permalink to an immutable public archive capture.

## Layers of confidence

Not all information on the web is equally reliable. To ensure transparent reporting, every field in an observation record is graded using three distinct confidence layers:

<Layers
  caption="The three confidence layers for observed information"
  layers={[
    {
      tag: "Seen",
      label: "Directly verified by the observer",
      detail: "Confirmed by running synthetic data through the tool, inspecting DevTools network traffic, or verifying official statutes.",
    },
    {
      tag: "Stated",
      label: "Claimed by the vendor or author",
      detail: "Reported in public marketing copy, user guides, or brochures, but not verified directly due to access gates.",
    },
    {
      tag: "Unknown",
      label: "Undisclosed on public pages",
      detail: "Information that cannot be determined without signing an agreement, creating an account, or contacting sales.",
    },
  ]}
/>

- **Seen**: High confidence. The observer loaded the tool, entered synthetic values, verified the offline behavior, and inspected network requests. If a tool claims to run in your browser and DevTools confirms zero outbound requests during calculation, browser confinement is marked as **Seen**.
- **Stated**: Moderate confidence. The vendor’s public website states that a tool calculates specific clauses or supports particular file formats, but the feature is behind an account wall. The feature is documented as **Stated** by the vendor.
- **Unknown**: Low confidence. Pricing, data retention policies, or backend architecture are not documented on public pages and would require contacting sales. These fields are marked as **Unknown**.

## Re-check an observation yourself

Every observation is published with the links and archived snapshots needed to reproduce the audit in about a minute. You do not need specialized software or programming experience to re-check our findings.

If your findings disagree with a published observation—for instance, if an updated tool now sends form data to a tracking server or moved behind a paywall—please report it. Open an issue on GitHub or email [contact@clearedstack.com](mailto:contact@clearedstack.com) so the record can be updated.

## What we never do

Observation is strictly non-intrusive. To protect user privacy, maintain legal compliance, and ensure clean-room integrity, we never:

- Access or inspect non-public, classified, Controlled Unclassified Information (CUI), or export-controlled material.
- Register user accounts, create passwords, provide company email addresses, or fill out lead capture forms.
- Request sales demonstrations, start free trials, or accept commercial software evaluation agreements.
- Circumvent paywalls, subscription gates, authentication forms, or IP rate limits.
- Solve, click through, wait out, or bypass CAPTCHAs, Turnstiles, or anti-bot verification challenges using any manual or automated method.
- Disregard `robots.txt` instructions or terms of service restrictions regarding crawling.
- Enter real company data, actual proposal text, real overhead rates, employee names, or live contract bids into any tool. All tests use published, synthetic dummy numbers.
- Decompile, reverse engineer, or copy source code, markup, CSS styles, or user interface designs from an observed tool.
- Conduct security audits, penetration testing, fuzzing, or vulnerability probing against external infrastructure.
