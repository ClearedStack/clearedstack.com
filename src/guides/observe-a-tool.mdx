In ClearedStack v3.1, observing an existing government-contracting tool is no longer a manual browser checklist—it is the job of `cs-02-observe`, a 100% deterministic, MIT-licensed Go worker running in the `cs-workers` Kubernetes namespace. Zero AI models run during observation. Given the same public URL or document, `cs-02-observe` produces the exact same structured observation record every time.

## Tiny HTTP pods first, headless browsers only when needed

Most public pages, government portals, and agency PDFs do not need a full web browser to inspect. By default, `cs-02-observe` runs as a tiny Go HTTP pod using roughly **30 MiB of RAM**. It claims a time-limited work lease from `hub-queue-api`, fetches the public target over plain HTTP, and runs deterministic extractors directly against the response.

Some vendor tools, however, render their calculators or tables entirely in client-side JavaScript. Only when a target is flagged as JavaScript-heavy does `cs-02-observe` spawn an **on-demand headless browser `Job` pod** (a temporary container that renders the page, records network requests using synthetic test inputs, and exits immediately). Keeping browsers out of the always-on worker pool lets the entire 17-pod ClearedStack platform fit comfortably on a single 4 GiB `k3s` node.

| Execution Mode | Footprint | When `cs-02-observe` Uses It |
| --- | --- | --- |
| **Default Go HTTP pod** | ~30 MiB RAM (always-on) | Static HTML marketing pages, `.gov` portals, downloadable PDFs, and server-rendered forms |
| **On-demand browser `Job` pod** | Ephemeral (created and deleted per job) | JavaScript-heavy single-page apps that require DOM rendering or client-side network inspection |

## Passive public boundaries

`cs-02-observe` is strictly passive and public. It only inspects pages accessible on the open web and never creates accounts, starts free trials, fills out lead-capture forms, enters real contracting data, or bypasses paywalls, `robots.txt` rules, or CAPTCHAs. If a tool sits behind a login or anti-bot challenge, observation stops at the public surface and records vendor claims as `Stated` rather than `Seen`.

## Deterministic sub-tools (`tools/<case>/`)

Real-world websites and agency documents vary widely. Instead of asking an AI model to guess at an unfamiliar page layout, `cs-02-observe` routes each target through deterministic sub-tools stored inside its own repository under `tools/<case>/`. Every sub-tool pairs a matching rule (`match.yaml`), predictable Go extraction logic (`extract.go`), and golden test fixtures (`fixtures/`) so automated tests verify the extractor never breaks.

| Sub-Tool | What It Matches and Extracts |
| --- | --- |
| `saas-marketing` | Public vendor landing pages and feature tables; extracts stated inputs, outputs, pricing model, and login gates |
| `gov-portal` | Federal `.gov` and `.mil` portals and calculators; captures cited FAR, DFARS, or NIST clauses and offline behavior |
| `agency-pdf` | Downloadable procurement PDFs, worksheets, and instructions; extracts form fields, rules, and publication dates |
| `<vendor-slug>` | Dedicated extractors for specific vendors whose page structure differs from standard layouts |

Each sub-tool outputs strict, schema-validated JSON covering the tool's core job, inputs, outputs, login requirement, tracking profile, license or copyright, price model, cited public rule, observation date, and confidence tier (`Seen`, `Stated`, or `Unknown`).

## Sealing raw snapshots behind the clean-room wall

While `cs-02-observe` fetches raw HTML, DOM captures, and PDFs to perform extraction, **those raw snapshots are sealed behind the clean-room wall**. Downstream build workers (`cs-06-build`) and specification compilers (`cs-05-provenance`) never see vendor markup, stylesheets, or client-side scripts. Only the sanitized, structured JSON facts and verified public regulations cross into the build pipeline—ensuring every published ClearedStack tool is an independent, clean-room MIT implementation.

## Failing closed into `needs_subtool`

When `cs-02-observe` encounters a page layout, table structure, or document format that none of its registered sub-tools recognize, it **never guesses**. Instead, it fails closed:

1. The worker pauses that item with the sanitized status `needs_subtool` (`E_NEEDS_SUBTOOL`) and continues processing the rest of the queue normally.
2. `cs-10-notify` opens a task in the `cs-02-observe` repository inside `cs-git` (mirrored publicly to GitHub) describing the unmatched pattern.
3. The paused item appears on the public `/guides/pipeline/` view so anyone can see why it stopped.
4. Once a contributor or maintainer adds a new deterministic sub-tool under `tools/<case>/` along with a golden fixture, `cs-runner` tests and builds the updated worker image with `ko` (no Docker), `cs-store` deploys it, and `hub-queue-api` **automatically replays** every item paused in `needs_subtool` for that pattern.

Every new edge case becomes permanent, tested, deterministic code—and every solved pattern automatically unblocks past items without human re-entry.
