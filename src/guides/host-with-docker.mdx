You do not have to use clearedstack.com to use ClearedStack. Everything is MIT licensed, and the repository includes a Dockerfile that packs the whole site into one small container. This guide covers a single server. For a cluster, see [Host on Kubernetes](/guides/host-on-kubernetes/). For no containers at all, see [Host as plain files](/guides/host-static-files/).

## Why host a copy

- Your company blocks outside websites, or allows only approved ones.
- You want the address a tool is loaded from to be one you control.
- You work on a network with no internet connection.
- You want a version that does not change until you decide to update it.

A copy you host behaves exactly like the public site. It still needs no database, no accounts and no outside connection.

## What you need

A machine with [Docker](https://docs.docker.com/get-docker/), git and an internet connection. The internet connection is only needed to build the image. Running it needs none.

Podman works too. Every command in this guide runs unchanged with `podman` in place of `docker`.

## Build the image

```bash
git clone https://github.com/ClearedStack/clearedstack.com.git
cd clearedstack.com
docker build -t clearedstack .
```

The first build takes a few minutes. It runs in two stages:

1. A Node.js container installs the dependencies and builds the site into plain files.
2. Those files are copied into a small nginx image. The Node.js stage is thrown away.

The result is an image of roughly 100 MB that holds a web server and the finished pages. It contains no database, no application server and no source code, and the web server runs as an ordinary user, not as root.

There is no published image to pull. You build your own, so you know exactly what is in it.

## Run it

```bash
docker run -d --name clearedstack --restart unless-stopped -p 8080:8080 clearedstack
```

Open `http://localhost:8080` and the site is there.

| Option | What it does |
| --- | --- |
| `-d` | Runs the container in the background |
| `--name clearedstack` | Gives it a name, so later commands can refer to it |
| `--restart unless-stopped` | Brings it back after a crash or a reboot |
| `-p 8080:8080` | Connects port 8080 on the server to port 8080 in the container |

If port 8080 is already taken, change the first number, for example `-p 3000:8080`. The second number has to stay 8080, because that is the port the web server inside listens on.

## Check that it works

```bash
docker ps --filter name=clearedstack
curl -I http://localhost:8080/
```

The first command should show the container with a status of `Up`. The second should print `HTTP/1.1 200 OK`, followed by the security headers the web server adds to every page.

## Run it with tighter settings

The image does not need to write to its own filesystem or hold any special privileges. You can tell Docker to enforce that:

```bash
docker run -d --name clearedstack --restart unless-stopped \
  --read-only --tmpfs /tmp \
  --cap-drop ALL --security-opt no-new-privileges \
  -p 127.0.0.1:8080:8080 clearedstack
```

| Option | What it does |
| --- | --- |
| `--read-only` | Makes the container’s filesystem read-only |
| `--tmpfs /tmp` | Gives nginx a small in-memory folder for its temporary files |
| `--cap-drop ALL` | Removes every Linux capability |
| `--security-opt no-new-privileges` | Stops any process inside from gaining privileges |
| `-p 127.0.0.1:8080:8080` | Accepts connections only from the server itself |

The last option is the one to use when something else on the same server handles HTTPS, as described below. Leave out `127.0.0.1:` if other machines need to reach port 8080 directly.

## Use Docker Compose

If you manage containers with Compose, this file does the same as the command above. Save it as `compose.yaml` in the repository folder:

```yaml
services:
  clearedstack:
    build: .
    image: clearedstack
    restart: unless-stopped
    read_only: true
    tmpfs:
      - /tmp
    cap_drop:
      - ALL
    security_opt:
      - no-new-privileges
    ports:
      - "127.0.0.1:8080:8080"
```

```bash
docker compose up -d --build
```

## Put it on your own domain

The container speaks plain HTTP on port 8080. For anything beyond your own machine, keep it behind a program that handles HTTPS and point that at the container.

With [Caddy](https://caddyserver.com), which obtains and renews certificates by itself, the whole configuration is:

```text
clearedstack.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

With nginx, add a server block that holds your certificate and passes requests through:

```nginx
server {
    listen 443 ssl;
    server_name clearedstack.example.com;
    ssl_certificate     /etc/ssl/certs/clearedstack.example.com.pem;
    ssl_certificate_key /etc/ssl/private/clearedstack.example.com.key;

    location / {
        proxy_pass http://127.0.0.1:8080;
    }
}
```

On an internal network, use a certificate from your organization’s own certificate authority.

## Set your own address

If your copy lives at a different address than clearedstack.com, change `url` in `src/data/site.ts` before you build:

```ts
url: "https://clearedstack.example.com",
```

The sitemap, the canonical links and the link previews use it. The pages work without this change. It only stops your copy from describing itself as the public site.

## Logs

The web server writes one line per request to the container’s output:

```bash
docker logs --tail 50 clearedstack
```

Those lines include the visitor’s IP address and the page requested. On your copy they are your records, kept under your rules. To keep no request log at all, add this line inside the `server` block of `docker/nginx.conf` and rebuild:

```nginx
access_log off;
```

## Update it

When the site changes, pull the new code, rebuild and replace the container:

```bash
git pull
docker build -t clearedstack .
docker rm -f clearedstack
docker run -d --name clearedstack --restart unless-stopped -p 8080:8080 clearedstack
```

The site is unavailable for a second or two while the container is replaced. Old images pile up after several updates. Remove the ones no container uses with:

```bash
docker image prune
```

To pin your copy to a known version instead of following every change, check out a specific commit before you build and tag the image with it:

```bash
git checkout <commit>
docker build -t clearedstack:$(git rev-parse --short HEAD) .
```

## Move it to a closed network

Build the image on a connected machine, then save it to a single file of about 27 MB:

```bash
docker save clearedstack | gzip > clearedstack.tar.gz
```

Carry that file across by whatever transfer process your network requires. On the other side, load it and run it:

```bash
docker load < clearedstack.tar.gz
docker run -d --name clearedstack --restart unless-stopped -p 8080:8080 clearedstack
```

The site loads its fonts and scripts from itself, so it works with no outside connection. [Run it on a closed network](/guides/closed-networks/) covers checksums, verification and updates in full.

## When something goes wrong

| What you see | Likely cause | What to do |
| --- | --- | --- |
| `port is already allocated` | Another program is using port 8080 | Change the first number in `-p`, for example `-p 3000:8080` |
| `container name is already in use` | An older container still exists | `docker rm -f clearedstack`, then run again |
| The build stops at `npm ci` | The build cannot reach the npm registry | Build on a machine with internet access, or pass your proxy with `--build-arg HTTPS_PROXY=...` |
| The build stops at `FROM` | The base images cannot be pulled | Check access to Docker Hub, or point the `FROM` lines at a mirror you trust |
| The page loads with no styling | The site is being served from a sub-folder of an address | Serve it from the root of a host name |
| The container exits at once with `--read-only` | The `--tmpfs /tmp` option is missing | Add it. nginx needs one writable folder |

To see why a container stopped, read its output with `docker logs clearedstack`.

## Remove it

```bash
docker rm -f clearedstack
docker rmi clearedstack
```

Nothing else is left behind. The container keeps no data.
