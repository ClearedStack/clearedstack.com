ClearedStack is an open public sandbox. Anyone can browse the Portal, inspect live worker queues, read sanitized errors, and propose fixes or improvements—without creating an account, remembering a password, or signing in.

## Clicking the edit button anywhere

Across the Portal, elements carry a small pencil edit button. Whether you spot a typo in a guide, a stale description on a tool card, or a configuration value that looks off, you can click that button directly on the page to suggest a change.

Opening the editor shows what the element currently holds and lets you submit a proposed update right from your browser. There is no account wall and no redirect to an external sign-in screen.

## How edits route to the owning repository

Behind the scenes, ClearedStack is split into focused repositories: the Portal itself (`clearedstack.com`) and the ten pipeline workers (`cs-01` through `cs-10`). You do not need to memorize which repository owns which part of the site.

Every editable element is mapped in `ownership_map.json`, which tells the Portal two things:

- **Where the change belongs:** Routes the proposal to `clearedstack.com` or the specific worker repository (`cs-01`..`cs-10`) that owns that data or rule.
- **What kind of change it is:** Classifies the proposal as `DATA` (catalog or content text), `CONFIG` (a rule or setting), or `ISSUE` (a problem report or sub-tool request).

Once submitted, the proposal enters the queue API (`hub-queue-api`) and waits in the [`/guides/decide/`](/guides/decide/) inbox (`cs-04-decide`).

## Live status tracking on your edit

After you submit a proposal, the edit button on that element turns into a live status pill so you can watch your contribution move through the system in real time:

| Status | What Is Happening |
| --- | --- |
| **Proposed** | Your submission passed anti-spam and schema checks and is waiting in [`/guides/decide/`](/guides/decide/). |
| **Approved** | The proposal was approved and routed to the internal Git server (`cs-git`). |
| **Building** | The build runner (`cs-runner`) is running automated tests and packaging the updated app or worker image. |
| **Live** | The app-store reconciler (`cs-store`) deployed the update, and your change is now live on the Portal. |

If a proposal is declined, it never alters the repository and the queue records the decision transparently.

## Stopping spam without logins or CAPTCHAs

Allowing anonymous edits on the open internet invites automated bots and scrapers. Instead of forcing human visitors to create accounts or solve frustrating image grids, ClearedStack uses a **5-layer anti-spam shield**:

| Layer | How It Works | Why It Respects Visitors |
| --- | --- | --- |
| **1. Browser proof-of-work** | When you click submit, your browser quietly solves a small cryptographic puzzle that takes about one second. | Invisible to real people, but expensive for bots trying to flood thousands of requests. |
| **2. Honeypot field** | A hidden form field that normal browsers never display or fill in. | Automated scrapers that fill every field are silently discarded. |
| **3. Daily-salted IP rate limit** | Converts your network address into a one-way hash using a secret salt that rotates daily, then caps submissions per hash. | Stops rapid-fire abuse without ever storing raw IP addresses. |
| **4. Strict schema check** | Verifies the target exists in `ownership_map.json`, enforces a 4 KB size limit, and strips all HTML and scripts. | Prevents malformed payloads or code injection before anything reaches storage. |
| **5. Review gate** | Every proposal sits in `pending_approval` inside `cs-04-decide` until explicitly approved. | Zero anonymous edits can ever touch `cs-git` or the live cluster automatically. |

This combination keeps the door wide open for helpful visitors while ensuring that nothing reaches the codebase or running cluster without passing automated safety checks and review.
