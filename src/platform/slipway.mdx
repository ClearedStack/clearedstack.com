## Overview & Role

Slipway (`v0.1.0-draft`, owned by the Slipway repository) is a lightweight MIT Go control-plane service running in the `clearedstack` namespace. It replaces traditional Docker-based CI runners with an event-driven, daemonless build controller.

When Plainforge receives a commit on `main` or a new tag, Slipway spawns an ephemeral Kubernetes `Job` pod to run the repository's deterministic golden fixture tests, compile an OCI image using `ko` (for Go services and workers) or rootless BuildKit (for web apps like Conn), sign the resulting digest with `cosign`, push it to Stow, and commit the new immutable digest back to `app.yaml` in Plainforge.

## Interfaces & Data Contracts

Slipway coordinates four internal control-plane interfaces:

1. **Webhook Intake (Plainforge -> Slipway):** Receives cluster-private push and tag webhooks from Plainforge. Commits containing `[skip-ci]` in the commit message are ignored to prevent recursive build loops.
2. **Ephemeral Job Orchestration (Kubernetes API):** Spawns short-lived `Job` pods in `clearedstack` with the appropriate builder:
   - `ko`: Compiles Go binaries (Plainforge, Stow, Slipway, Bosun, Muster, and Trawl through Foghorn) directly into minimal OCI images with zero Dockerfile or Docker daemon.
   - **Rootless BuildKit:** Builds multi-layer container images for Next.js web workloads (Conn) inside an unprivileged, rootless pod.
3. **Test, Sign & Push (`Job` -> Stow):** Executes golden fixture tests before building. Passing builds are signed with `cosign` and pushed by `sha256` digest to Stow.
4. **Manifest Pinning (Slipway -> Plainforge):** Updates the pinned image digest in `app.yaml` inside Plainforge with a `[skip-ci]` commit so Bosun can reconcile the new release.

## Sub-Tools & Failure Modes

Slipway is a control-plane build controller and does not host `tools/<case>/` deterministic sub-tools (`subTools: []`).

| Failure Mode | Trigger | System Behavior & Recovery |
| --- | --- | --- |
| **Golden test failure** | A commit breaks a deterministic fixture or unit test | The build `Job` aborts before packaging or pushing; broken images never enter Stow. |
| **Build or push timeout (`E_TIMEOUT`)** | Slow dependency fetch or registry stall | The `Job` terminates cleanly and reports `E_TIMEOUT`; no partial digest is written to `app.yaml`. |
| **`cosign` signing failure** | Missing or invalid signing key material | Image push is blocked or left unsigned; Bosun refuses to roll out unsigned digests. |
| **Memory preemption** | Node memory tightens during a build `Job` | Low PriorityClass allows `k3s` to preempt ephemeral build `Job`s first while protecting Logbook, Muster, and Bosun; deterministic builds can be safely retried. |
| **Recursive CI loop** | Slipway committing `app.yaml` back to Plainforge | Prevented deterministically by tagging `app.yaml` commits with `[skip-ci]`. |

## Security & Clean-Room Boundaries

- **Zero Docker daemon:** No Docker socket (`/var/run/docker.sock`), privileged containers, or root-level build daemons exist anywhere on the host or inside build `Job` pods.
- **Rootless & unprivileged:** Both the Slipway controller and its spawned `ko` / rootless BuildKit `Job`s run as non-root users with dropped Linux capabilities and no privilege escalation.
- **Cluster-private only:** Slipway has no public Ingress and accepts webhooks exclusively from Plainforge under default-deny `NetworkPolicy` rules.
- **Supply-chain integrity:** Every published image is tested against golden fixtures and cryptographically signed with `cosign` before `app.yaml` is updated.
