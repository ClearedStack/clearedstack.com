`cs-git` (`v0.1.0-draft`, owned by `cs-git`) is a clean-room, MIT-licensed Go Git server running in the `clearedstack` control-plane namespace. It replaces heavy third-party forges such as Forgejo—eliminating 40+ database tables and hundreds of megabytes of RAM—while serving as the cluster's primary source of truth for code and configuration.

## Overview & Role

ClearedStack treats the cluster as primary and GitHub as the public mirror:

- **Headless Primary Git Server:** Hosts bare `.git` repositories for `clearedstack.com`, all 10 deterministic workers (`cs-01`..`cs-10`), sub-tools, and `app.yaml` deployment manifests.
- **Webhook & Mirror Trigger:** Whenever a commit lands on `main` or a new tag is created, `cs-git` fires a push webhook to `cs-runner` and push-mirrors source commits and tags to GitHub.
- **Zero Web UI / Account Overhead:** Public browsing, status inspection, and anonymous `✎ Edit` proposals happen in `clearedstack-web`, so `cs-git` needs no user accounts, issue UI, or PR web frontend.

## Interfaces & Data Contracts

| Peer / Target | Direction | Protocol / Mechanism | Data Contract |
| --- | --- | --- | --- |
| **`cs-10-notify`** | Inbound | Cluster-private Git / Patch API | Commits approved public edits (from `cs-04-decide`) and opens fingerprinted `needs_subtool` tasks in owning repos |
| **`cs-runner`** | Outbound / Inbound | Push webhook + Git commit | Receives push webhooks on `main`/tag updates to start builds; commits updated `app.yaml` image digests tagged `[skip-ci]` |
| **`cs-store`** | Inbound | Cluster-private Git read | Watches `app.yaml` manifests in `cs-git` to reconcile deployments via Server-Side Apply |
| **GitHub** | Outbound | HTTPS Git push-mirror | Mirrors source commits and tags on change; **zero container images** are ever pushed to GitHub |

## Failure Modes & Recovery

- **GitHub Unreachable / Rate-Limited:** Because `cs-git` is primary, internal commits, `cs-runner` builds, and `cs-store` deployments continue operating normally even if outbound mirroring to GitHub is temporarily unreachable.
- **Build Loop Prevention:** Digest updates written back by `cs-runner` to `app.yaml` are tagged `[skip-ci]` so `cs-git` does not re-trigger an infinite build loop.
- **Volume Loss / Corruption:** `cs-git` holds one of the cluster's three Persistent Volume Claims. Nightly backups archive the bare repositories, encrypt them client-side with `age`, and transfer them off-node. The automated monthly restore drill mounts the restored bare repositories in an isolated scratch area and runs Git consistency checks to prove recoverability.
- **Pod Restart:** High Priority Class protects `cs-git` from eviction; on restart, `k3s` reattaches the PVC with all bare repositories intact.

## Security & Clean-Room Boundaries

- **ClusterIP Only:** `cs-git` has zero public Ingress and is unreachable from the open internet. Default-deny `NetworkPolicy` restricts cluster-internal access to authorized control-plane peers.
- **No Unapproved Public Commits:** Anonymous `✎ Edit` proposals cannot reach `cs-git` directly; they must pass the 5-layer anti-spam shield in `hub-queue-api` and explicit human approval in `cs-04-decide` before `cs-10-notify` writes a commit.
- **Source-Only Public Mirror:** Only source code commits and tags mirror to GitHub; signed OCI container images remain strictly internal inside `cs-registry`.
- **Clean-Room MIT Licensing:** Written from scratch in Go under the MIT license, with no upstream forge license or dependency baggage.
- **Unprivileged Execution:** Runs as non-root with dropped Linux capabilities and no privilege escalation.
