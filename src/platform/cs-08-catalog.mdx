## Overview & Role

`cs-08-catalog` is the catalog publication worker in the `cs-workers` namespace (`ownerRepo: cs-08-catalog`, version `v0.1.0-draft`). Split out of the original Stage 9 (List) alongside `cs-07-verify`, its job is to publish verified, linked, merged, and retired entries—complete with provenance links—to the `clearedstack.com` catalog (`/tools`).

`cs-08-catalog` is a 100% deterministic Go service with zero AI at runtime. It never builds code or runs verification checks itself; it only publishes outcomes that have already passed `cs-07-verify` or been determined in `cs-04-decide`.

## Runtime & Resource Budget

| Property | Value |
| --- | --- |
| **Service / Repo** | `cs-08-catalog` |
| **Namespace** | `cs-workers` |
| **Kind** | `worker` (100% deterministic Go, zero runtime AI) |
| **Version** | `v0.1.0-draft` |
| **RAM Budget** | `30 MiB` |
| **Sub-Tools** | None (`[]` — uniform catalog publication logic) |
| **Local Spool** | `/var/spool/cs` (buffers publication acknowledgements if `hub-queue-api` restarts) |
| **Contract Version** | `CONTRACT_VERSION=v1` (owned by `clearedstack.com`) |

`cs-08-catalog` runs under the Standard Kubernetes priority class, keeping baseline memory around `30 MiB` and yielding before High-priority control-plane pods on a single 4 GiB `k3s` node.

## Interfaces & State Transitions

`cs-08-catalog` communicates exclusively with `hub-queue-api` over cluster-private HTTP using its Kubernetes ServiceAccount identity (`lease`, `heartbeat`, `complete`, `fail`, `needs_subtool`), processing `urgent` items before `normal` and `normal` before `backfill`. It has zero direct access to `postgres`.

| Source State | Target State | Trigger & Catalog Action |
| --- | --- | --- |
| `building` | `live` | `cs-07-verify` passed all 5 conditions; publishes active tool entry and provenance links to `/tools`. |
| `scored` | `linked` | Owner in `cs-04-decide` chose **Link**; publishes external reference to an existing free, private tool (avoiding duplicate rebuild). |
| `scored` | `merged` | Owner in `cs-04-decide` chose **Merge**; publishes catalog note folding scope into the parent tool repository. |
| `live` | `retired` | Governing regulation repealed or superseded (detected by `cs-09-monitor`); archives active listing while retaining historical note. |

Completed publication payloads are staged in `/var/spool/cs` before `hub-queue-api` commits the state transition to `core.*` and refreshes `pub.*` views for `clearedstack-web`. Public tool source repositories in `cs-git` are mirrored to GitHub on change (with zero container images pushed to GitHub).

## Sub-Tools & Failure Modes

`cs-08-catalog` defines **no per-case sub-tools** (`subTools: []`) because catalog entry generation follows a single deterministic schema enforced by `hub-queue-api`.

| Error Code | Trigger | Pipeline Behavior |
| --- | --- | --- |
| `E_PARSE` | Missing provenance block, missing `cs-07-verify` pass attestation, or invalid catalog metadata | Fails cleanly without publishing; reports sanitized error to `hub-queue-api` for deduplication by `cs-10-notify`. |
| `E_TIMEOUT` | `hub-queue-api` or catalog sync endpoint times out | Result stays safely staged in `/var/spool/cs` and retries with backoff until acknowledged. |
| `E_NEEDS_SUBTOOL` | Unsupported catalog entry type or schema version mismatch | Fails closed, pauses item in `needs_subtool`, and awaits a deterministic update deployed via `cs-store`. |

## Security & Clean-Room Boundaries

- **Zero direct database access:** Network policies block `cs-08-catalog` from `postgres`, `cs-git`, and `cs-registry`; all state writes flow through `hub-queue-api` transactions.
- **Unprivileged pod posture:** Non-root user, dropped Linux capabilities, no privilege escalation, and read-only root filesystem outside `/var/spool/cs`.
- **Provenance & attribution:** Every published `live` or `linked` entry preserves the deterministic Go-template provenance note stamped by `cs-05-provenance` and carries no raw `cs-02-observe` snapshots.
- **Sanitized observability:** Cluster internals are stripped by `cs-store` before any worker health or error state appears on `clearedstack-web`.
