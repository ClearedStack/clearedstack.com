The catalog is the part of ClearedStack a contractor sees. Behind it is a design for choosing and building tools in the open: a pipeline of ten small programs that finds ideas, screens and scores them, and builds each tool from the public rule, on a small cluster that anyone can copy. This page is the map. The other pages in this section fill in each part.

## The parts

The project is split into small repositories, each with one job.

| Group | Repositories | What it holds |
| --- | --- | --- |
| The hub | `clearedstack.com` | This website, the catalog, the guides, and the shared rules the other parts agree on |
| The pipeline | `cs-01-intake` to `cs-10-notify` | Ten workers, one for each stage from finding an idea to watching a published tool |
| The control plane | `cs-git`, `cs-registry`, `cs-runner`, `cs-store` | Four small services that hold the code, build it, store the images and deploy them |
| The tools | One repository for each tool | The browser tools themselves, each able to be read, forked and hosted alone |

Keeping the parts separate has three effects. A change to one worker rebuilds and redeploys only that worker. The worker that looks at existing tools and the worker that builds new ones live in different repositories, which is how the [clean-room rule](/platform/clean-room-and-credit/) is enforced. And any one part can be rolled back without touching the rest.

The full list, with each component’s job and memory budget, is on the [Platform](/platform/#components) page.

## Three loops that keep it current

A catalog decays. Regulations change, the pages a worker reads are redesigned, and readers spot mistakes. The design turns each of those into a loop that ends in a tested change.

<Flow
  caption="What happens when something needs to change"
  direction="down"
  steps={[
    { tag: "1 · Signal", label: "Something needs attention", detail: "A reader proposes an edit, a watched regulation changes, or a worker meets a page it has no rule for." },
    { tag: "2 · Gate", label: "A person decides", detail: "Proposals are checked automatically, then wait for the owner’s approval." },
    { tag: "3 · Route", label: "It goes to the right repository", detail: "The approved change, or a task describing the problem, lands in the repository that owns that part." },
    { tag: "4 · Build", label: "Tested and built", detail: "The repository’s tests run, and a new signed image is built." },
    { tag: "5 · Deploy", label: "Rolled out, and paused work resumes", detail: "The new version is deployed, and anything that was waiting on it is run again." },
  ]}
/>

- **A page no rule covers.** A worker never guesses. It pauses the item, and a task is opened to write a rule for that case. When the rule ships, the paused items run again. See [Sub-tools](/platform/pipeline/#sub-tools-one-rule-for-each-case).
- **An edit from a reader.** Anyone can propose a change without an account. Nothing is applied until the owner approves it. See [Public edits](/platform/public-edits/).
- **A change in the rules.** A watcher compares official sources on a schedule. When a cited clause changes, the affected tool is sent back to be checked and rebuilt. See [cs-09-monitor](/platform/pipeline/#watching-and-routing).

## Four rules everything follows

1. **No AI when it runs.** No worker and no tool calls an AI model. The same input gives the same output on any machine, and every result can be traced to a line of code. AI is used only to help write that code, under review. See [How AI is used](/platform/built-with-ai/).
2. **Stop instead of guessing.** A worker that meets something it has no rule for pauses that item and says why. In contracting, a guess is worse than a gap.
3. **Hide the network, show the logic.** The code, the rules, the scores and the decisions are public. Addresses, credentials and the layout of the cluster are not. See [what stays private](/platform/public-edits/#what-is-public-and-what-is-private).
4. **One person is accountable.** The pipeline recommends. A named human owner decides, and overrides are written down with a reason.
