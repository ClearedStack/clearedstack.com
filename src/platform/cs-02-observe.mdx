## Overview & Role

`cs-02-observe` (`v0.1.0-draft`) is the deterministic observation worker in the ClearedStack v3.1 pipeline, replacing the original Stage 3 (Observe). Implemented as a Go service in the `cs-02-observe` repository under the MIT License, it inspects public web pages, `.gov` portals, and agency PDFs using repeatable extractors and zero runtime AI.

Its core responsibilities are:

- **Public-only inspection:** Fetch open-web vendor marketing pages, government portals, and procurement PDFs without logging in, bypassing paywalls, or submitting forms.
- **Deterministic fact extraction:** Produce strict, schema-validated JSON capturing a candidate tool's core job, inputs, outputs, login requirement, tracking profile, license or copyright, price model, cited public rule, observation date, and confidence tier (`Seen`, `Stated`, or `Unknown`).
- **Clean-room sealing:** Seal all raw HTML, DOM snapshots, screenshots, and downloaded PDFs behind the clean-room wall so downstream specification and build workers (`cs-05-provenance` and `cs-06-build`) never see vendor markup, stylesheets, or client-side scripts.

## Runtime & Resource Budget

`cs-02-observe` runs in the `cs-workers` Kubernetes namespace under the **Standard (Workers)** priority class, with ephemeral headless browser `Job` pods scheduled under **Low (Ephemeral Jobs)**.

| Attribute | Value |
| --- | --- |
| **Worker ID / Repo** | `cs-02-observe` |
| **Namespace** | `cs-workers` |
| **Kind / Version** | `worker` · `v0.1.0-draft` |
| **Baseline RAM Budget** | `30 MiB` (always-on Go HTTP pod) |
| **Ephemeral Footprint** | On-demand headless browser `Job` pods (created and deleted per JS-heavy target) |
| **Runtime AI Calls** | `0` (100% deterministic Go + YAML rules) |
| **Local Spool** | `/var/spool/cs` (persists completed extraction payloads across `hub-queue-api` restarts) |
| **Build & Deploy** | Built with `ko` (no Docker) by `cs-runner`, signed with `cosign` in `cs-registry`, deployed by `cs-store` via Server-Side Apply |

Keeping headless browsers out of the always-on worker pool preserves the ~300 MiB baseline worker footprint so the full 17-pod ClearedStack platform fits on a single 4 GiB `k3s` node.

## Interfaces & State Transitions

`cs-02-observe` communicates exclusively with `hub-queue-api` in the `clearedstack` namespace over cluster-private HTTP authenticated via its Kubernetes ServiceAccount (`CONTRACT_VERSION=v1`). It never connects directly to `postgres`, `cs-git`, or `cs-registry`.

- **Queue consumption:** Polls `hub-queue-api` using `lease`, `heartbeat`, `complete`, `fail`, and `needs_subtool`, draining priority lanes in strict order: `urgent` → `normal` → `backfill`.
- **Inbound states:**
  - `recorded` — Newly deduplicated `PA-XXXX` candidates from `cs-01-intake`.
  - `observed` (re-queued) — Items returned from `needs_subtool` replay after a sub-tool fix ships, `parked` items whose blocker cleared in `cs-09-monitor`, or `linked` items flagged for drift.
- **Outbound transitions:**
  - `observed` — Extraction succeeded; sanitized structured JSON facts are stored in `core.*` and raw captures remain sealed behind the clean-room wall.
  - `needs_subtool` — Fail-closed pause (`E_NEEDS_SUBTOOL`) when no registered sub-tool matches the target layout.
- **Spool durability:** Extracted payloads are written to `/var/spool/cs` before acknowledging `complete` to `hub-queue-api`, preventing lost work during control-plane restarts.

## Sub-Tools & Failure Modes

Per-site and per-format variations live inside the `cs-02-observe` repository under `tools/<case>/`, where each sub-tool pairs a `match.yaml` rule, deterministic `extract.go` logic, and golden `fixtures/`.

| Sub-Tool | Target Pattern & Behavior |
| --- | --- |
| `saas-marketing` | Public vendor landing pages and feature tables; extracts stated inputs, outputs, pricing model, and login gates. |
| `gov-portal` | Federal `.gov` and `.mil` portals and calculators; captures cited FAR, DFARS, or NIST clauses and offline behavior. |
| `agency-pdf` | Downloadable procurement PDFs, worksheets, and instructions; extracts form fields, rules, and publication dates. |
| `on-demand-browser-job` | Ephemeral headless browser `Job` spawned only for JavaScript-heavy single-page apps to render the DOM and inspect client-side network calls using synthetic test inputs. |
| `<vendor-slug>` | Dedicated extractors for specific vendors whose public page structure differs from standard layouts. |

### Sanitized Failure Modes

`cs-02-observe` never guesses when an extraction fails or encounters an unknown layout:

| Error Code | Trigger | Platform Behavior |
| --- | --- | --- |
| `E_NEEDS_SUBTOOL` | Page layout, table, or PDF format matches no registered `tools/<case>/` sub-tool. | Fails closed to `needs_subtool`. `cs-10-notify` opens a deduplicated task in `cs-02-observe` on `cs-git`; once a new sub-tool and fixture deploy, `hub-queue-api` auto-replays paused items. |
| `E_TIMEOUT` | Upstream public page, PDF download, or ephemeral browser `Job` exceeds deadline. | Item remains safely queued for bounded retry; `cs-store` strips cluster internals before surfacing status. |
| `E_PARSE` | Malformed HTML, corrupted PDF, or schema validation failure on extracted JSON. | Halts item cleanly and reports fingerprinted error via `cs-10-notify` without emitting partial data. |

## Security & Clean-Room Boundaries

- **Passive public boundaries:** `cs-02-observe` never creates accounts, starts free trials, submits lead-capture forms, enters real contracting data, or circumvents paywalls, `robots.txt`, or CAPTCHAs. If a tool sits behind a login or anti-bot gate, observation stops at the public surface and records vendor claims as `Stated` rather than `Seen`.
- **Strict clean-room wall:** Raw HTML, DOM trees, stylesheets, client-side scripts, and binary PDFs are sealed at `cs-02-observe` and never cross into `cs-05-provenance` or `cs-06-build`. `hub-queue-api` enforces this contract boundary by rejecting any build payload containing raw observation artifacts.
- **Pod hardening & network policy:** Runs as an unprivileged non-root user with dropped Linux capabilities, no privilege escalation, and a read-only root filesystem (writable only at `/var/spool/cs`). Default-deny Kubernetes `NetworkPolicy` allows outbound HTTP/HTTPS for public fetches and cluster-private HTTP to `hub-queue-api`, while blocking direct access to `postgres`, `cs-git`, and `cs-registry`.
